# Start by what you need

GlassesResearch contains consumer, research, historical, and developer material. Start with the path that matches the question you are trying to answer.

## I am buying my first smart glasses

Start with the [Buyer Guide](../buyers/BUYER_AND_OPENNESS_GUIDE.md), then browse [The List](../models/THE_LIST.md) and use the [Comparison Engine](COMPARISON_ENGINE.md) when you have narrowed the field.

Pay particular attention to prescription support, offline behavior, account requirements, companion-app dependence, repairability, battery replacement, and whether advertised features continue working without a vendor cloud service.

## I am comparing specific devices

Go directly to the [Comparison Engine](COMPARISON_ENGINE.md). It uses consistent field definitions across models and provides supporting sources where available.

## I am a developer or reverse engineer

Start with [Developer Resources](../hacking/README.md) and [Community & Development](../resources/COMMUNITY_AND_DEVELOPMENT.md), then follow model-specific links to SDKs, APIs, BLE research, firmware, FCC filings, recovery notes, alternative applications, packet captures, and community projects.

## I am researching the industry

Use the [Industry Timeline](INDUSTRY_TIMELINE.md), [Research and News](news/README.md), [Research Library](../evidence/README.md), and [Historical Archive](HISTORICAL_ARCHIVE.md).

The timeline emphasizes major milestones; the archive and research library provide supporting detail and sources.

## I am a journalist

Start with the [Industry Timeline](INDUSTRY_TIMELINE.md) and [Research Standards](RESEARCH_STANDARDS.md). Timeline events include stable identifiers, sources, and citation-friendly links. For a disputed claim or correction, use [Challenge Our Research](RESEARCH_CHALLENGES.md).

## I am a manufacturer or project maintainer

Check the relevant model or project entry. If something is inaccurate, incomplete, or superseded, submit a [Research Challenge or correction](RESEARCH_CHALLENGES.md) with primary documentation where available.

## I want to contribute

See [Contribute](CONTRIBUTE.md) and the [Hall of Contributors](CONTRIBUTORS.md). Contributions can include specifications, manuals, firmware metadata, SDK links, repair findings, protocol research, teardown information, corrections, preservation work, and documented hands-on observations.
